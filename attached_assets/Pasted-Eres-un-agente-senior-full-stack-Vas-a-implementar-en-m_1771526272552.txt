Eres un agente senior full-stack. Vas a implementar en mi app un sistema de:
1) Notificaciones (in-app) ligadas a Proyecto + Actor (quien asigna) + Entity (tarea/comentario/etc).
2) Chat interno por proyecto (conversaciones tipo “project channels”).
3) En el chat, ability de “adjuntar”/linkear objetos del sistema: Proyecto y Tarea (message_links).

OBJETIVO MVP (prioridad):
A. Notificaciones in-app para evento: task_assigned
B. Chat por proyecto con mensajes en tiempo real
C. Link de tarea/proyecto dentro de mensajes (chips + deep links)
D. UI básica: Campana de notificaciones + Pantalla de chat por proyecto + Adjuntar referencia

REGLAS DE PRODUCTO:
- Cada notificación debe tener: recipient_id, actor_id, project_id (si aplica), entity_type, entity_id, type, payload JSON, read_at, created_at.
- Las notificaciones deben abrir (deep link) al objeto: si entity_type=task -> abrir TaskDetail dentro del Project.
- Permisos: un usuario solo puede ver proyectos donde es miembro. Igual para conversaciones y mensajes.
- Chat: modelo base “conversation per project”. No DM todavía.
- Mensajes pueden tener 0..N links (message_links) a entity_type = project|task.
- Debe existir “last_read_at” por miembro para unread counts.

- Si ya existe auth, reutilízalo. Si no existe, agrega Supabase Auth Email/Password mínimo.

ENTIDADES / TABLAS (crear si no existen):
1) projects (id, name, created_at)
2) project_members (project_id, user_id, role, created_at)

3) tasks (id, project_id, title, description, status, assigned_to, created_by, due_date, created_at)

4) notifications (
   id uuid pk,
   recipient_id uuid references auth.users,
   actor_id uuid references auth.users,
   project_id uuid references projects,
   entity_type text, -- 'task' | 'project'
   entity_id uuid,
   type text,        -- 'task_assigned' etc
   payload jsonb,
   read_at timestamptz null,
   created_at timestamptz default now()
)

5) conversations (
   id uuid pk,
   project_id uuid references projects,
   type text default 'project', -- for future: dm/group
   name text null,
   created_at timestamptz default now()
)

6) conversation_members (
   conversation_id uuid references conversations,
   user_id uuid references auth.users,
   role text,
   last_read_at timestamptz default now(),
   created_at timestamptz default now(),
   primary key (conversation_id, user_id)
)

7) messages (
   id uuid pk,
   conversation_id uuid references conversations,
   sender_id uuid references auth.users,
   body text,
   created_at timestamptz default now()
)

8) message_links (
   id uuid pk,
   message_id uuid references messages,
   entity_type text, -- 'project'|'task'
   entity_id uuid,
   project_id uuid null,
   created_at timestamptz default now()
)

RLS (muy importante):
- projects: select solo si user es miembro via project_members.
- project_members: select solo si pertenece al mismo project donde es miembro (o si role admin).
- tasks: select/insert/update solo si user es miembro del proyecto.
- notifications: select/update solo si recipient_id = auth.uid().
- conversations: select solo si user es miembro del proyecto (o miembro conversation_members).
- conversation_members: select solo si user pertenece a esa conversation.
- messages: select/insert solo si user es miembro de esa conversation.
- message_links: select solo si user puede ver el message.
